# 2026-11-10｜アナログ名機の設計を「音声経路」と「制御経路」に分けて学ぶ

分類: 基礎設計比較 / 音作りの原理 / 将来の製品設計  
成熟度: **メーカー公式マニュアル・公開資料で確認した構造＋DinMeterへの応用仮説**  
実機録音・波形測定: **未実施**。Minimoogについては公式PDFの再取得が必要（後述）。

## 1. まず区別すべき二つの流れ

減算合成型シンセでは、おおむね次の2種類の信号がある。

- **音声経路（Audio path）**：OSC等の音の素材 → MIXER → FILTER → AMPLIFIER → 出力。これらを順番に通ることで**実際に鳴る音**を変える。
- **制御経路（Modulation/Control path）**：鍵盤・LFO・ENV・ホイール等が上記の音声処理パラメータを変化させる。制御信号自体は通常、音声出力されるとは限らない。

**重要**: DinMeterのSAM2695は音声経路の大半を**チップ内部**で処理し、ESP32はMIDI等で制御する。「OSCを3つ」と呼んでも独立した外部音声信号のミキサーに直接入れることはできない。

## 2. 名機別に何を学べるか

### A. Minimoog Model D — 音の素材・ミキサー・フィルター・コンター

構成として確認されている要素: 3つのOSC、ノイズ、音声ミキサー、フィルター、フィルターENV（Contour）、ラウドネスENV、Glide、モジュレーション。

**設計上の着眼点**: 「何の音を作るか」を考えるとき、波形そのもの、各OSCの音量比、フィルター、発音時の明るさ変化、音の立ち上がり・終わりを**分けて扱う**。名機の考え方を取り入れる場合も「同じ名前のパラメータを用意する」より「音声経路のどの段階で音がどう変わるか」を先に見る。

**DinMeterへの問い**: GM-ROM素材を3レイヤーに重ねた場合、フィルター処理が本当に同じ音色効果を得られるか。3つのOSCが持つ固有音色の内部波形・内部ENVが、狙った音にどう影響するか。

*根拠*: [Moog公式マニュアルの配布元URL](https://api.moogmusic.com/sites/default/files/2022-11/Minimoog_Model_D_Manual.pdf) による資料紹介を確認。ただし直接PDF取得時に404となったため、**この項目は暫定要約**。回路方式や全機能を確定する前に別の公式版を取得すること。**Moogの回路図やDSPの設計を読んだ扱いにはしない。**

### B. KORG MS-20 — 「音声処理」と「変調」を分解する

[KORGのオリジナル日本語マニュアル](https://www.korg.com/jp/support/download/product/1/67/)の**ブロック図（誌面p.2）**で次の流れを確認した。

`VCO 1 + VCO 2 (RING可) → MIXER → VCHPF → VCLPF → VCA → SIG OUT`

別に、MG（Modulation Generator）、EG1（Delay/Attack/Release）、EG2（Hold/Attack/Decay/Sustain/Release）、S/H、外部入力・外部信号処理が描かれている。パッチによりこれらの制御や音声経路を組み替える発想が核にある。

**学ぶ原理**: HPF→LPFの直列は、低域を整理した後に高域を絞るなど、LPF一つだけとは違う作り方を与える。また、音声処理の直列接続と、複数パラメータへの変調配線は別概念である。

**DinMeterへの問い**:
- SAM2695の内蔵TVF/GS制御で、LPF以外の帯域加工をどの程度できるか。できない場合は外付けエフェクト基板が必要か。
- 現行`currentPreset.env[]`と実際のSAM内蔵ADRを、ユーザーUIにどう分けて示すべきか。

**重要な反証**: 「MS-20のようなHPFをUI上で追加すれば音が出せる」という推論は成り立たない。チップがHPFを提供するか、外部オーディオDSPが必要かをまず確認する。

### C. Sequential Prophet-5 — 音声ごとに独立するPoly Mod

[Sequential Prophet-5公式User's Guide 1.3](https://www.sequential.com/wp-content/uploads/2021/02/Prophet-5-Users-Guide-1.3.pdf) の誌面pp.34–35（PDF通算45頁付近）を確認。

Poly Modのソースは**Filter ENV、Oscillator B**。ディスティネーションは**Oscillator A Frequency、Oscillator A Pulse Width、Filter Cutoff**。ポリフォニックの各音声でそれぞれ変調される。

**学ぶ原理**: 「LFOやENVが何個あるか」よりも、**変調の持ち主が1音ごとなのか、楽器全体で共有なのか**が重要。たとえば3和音の3音それぞれでENV開始時間が違うと、和音の色が時間とともに変化する。

**DinMeterとの重要な違い**:
- 現行の`envRuntime[]`/`lfoRuntime[]`はESP32上の共通状態として管理され、入力ノートごとの完全な独立ENV/LFOではない。
- OSC1–3のMIDIチャンネルを分けることと、**各キーのボイスを独立変調することは別**。
- 現行のMOD更新は最大およそ31回/秒である。オーディオレートのFM/PWMを同じ方式で再現することはできない。

**将来の使い道**: パッドやブラスの音色で変調を単一の共通エンベロープとするのか、将来の音源変更・DSP追加時に音声ごとのENVを持たせるのか、設計判断の基準に使える。

### D. Surge XT — 「Per-voice / Global」を現代的に設計する

[Surge XT公式マニュアル](https://surge-synthesizer.github.io/manual-xt/)では、Voice LFOとScene LFOを分け、Voiceの変調は音声単位、Sceneの変調は共通単位として扱う。またフィルター方式はLPFだけでなくHPF/BPF/Notch等を提供し、複数のオシレーターアルゴリズムを扱う。

[公開ソース・設計メモ](https://github.com/surge-synthesizer/surge/blob/main/doc/Surge%20Architecture.md) はDSP・ボイス管理が`src/common`にあることなどを記す。ただし**個別関数のロジックはまだ未精読**であり、後日ソースを見て確認する。

**学ぶ原理**: UIのノブが変調しているのは単一の`cutoff`値なのか、各音声が持つcutoff値なのか。これを区別しないと、ポリ演奏・レガート・LFOリトリガ時に期待がズレる。

**反証**: SurgeのDSPコードをSAM2695のMIDI制御マイコンにそのまま移植できるわけではない。DSPそのものはチップのPCM音声経路に介入できない。GPL-3.0等のライセンスも直接移植の障害になりうる。

## 3. DinMeterで何が可能か — 判断を急がない

| 設計原理 | 現行構成での可能性 | ひとまずの扱い |
|---|---|---|
| 複数音色素材のレイヤー、デチューン、オクターブ | **実装あり**（3 OSC + GM） | 録音比較で効果を検証 |
| フィルターcutoff・レゾナンスの制御 | **実装あり**（SAM2695 TVF/GS） | 連続操作時の可聴範囲を確認 |
| AMP/Filter用のMOD ENV・LFOルーティング | **一部実装あり**（MIDIパラメータ更新） | 独立制御と共有制御の責務を整理 |
| 真のPer-voice ENV/LFO | **現行コードでは未実装** | SAM2695の音声ごと制御能力が制約 |
| 各OSCのAudio-rate同期・PWM・リング変調 | **直接実現できる根拠は未確認** | MIDIレイヤーだけでは再現困難。音源変更/外部DSP候補 |
| MS-20型の直列HPF→LPF、フィルター飽和 | **実現可否未確認** | サンプル加工か外部オーディオ処理かを先に判定 |
| Prophet-5型の多声・音声ごとの揺らぎ | **擬似的な近似は検討余地** | チャンネル数、MIDI発音数、分離管理コストが増える |
| アナログ音の「温かさ」 | **単一の原因ではない** | 比較条件をそろえた聴感・スペクトル検証が必要 |

## 4. 将来役立つ「設計の問い」

1. **音源の中**で波形を変えるのか、**音源の後**にエフェクトを入れるのか、MIDIの**パラメータ制御**だけで済ませるのか。
2. パッチを見た時に、音声経路と変調経路が頭の中で追えるUIになっているか。
3. ノートごとに変調が必要なのか、全体で共通の変調でも目的の音に十分か。
4. 各OSCを一つずつミュートして「太さ」の寄与を実際に聴き分けているか。
5. 既存名機の音を真似たい時、**波形・VCFの質・飽和・ENVの動き・演奏操作**のどの差が支配的かを反証可能な形で切り分けられるか。
